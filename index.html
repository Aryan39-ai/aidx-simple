Research areas

01

Trustworthy AI Agents

When can an AI agent be trusted to use tools independently?

We explore how tool permissions, action logs and resource limits affect the reliability of AI agents.

Project: can an agent be trusted with real tools?

02

AI Security

How can misleading inputs affect a chain of AI agents?

We investigate how harmful instructions spread between agents and which safeguards can limit their effects.

Project: how far does a poisoned input travel?

03

Human–AI Decision Making

Do AI explanations help people make better decisions?

We examine whether explanations improve decisions or mainly change people's confidence.

Project: does an explanation change the decision?

Projects

Projects

01

Can an agent be trusted with real tools?

Honours / Summer intern · Sample supervisor profile · Sample project

Give an agent a small set of real tools and a budget, then log every step to see where it goes wrong when nobody is checking.

A student would build the sandbox and compare how two agents spend the same budget.

Research area: Trustworthy AI Agents

02

How far does a poisoned input travel?

Honours / PhD · Sample supervisor profile · Sample project

One bad input goes into a chain of agents that trust each other. The project measures how many steps it survives, and what stops it.

A student would write the test cases and turn the results into a dataset.

Research area: AI Security

03

Does an explanation change the decision?

Honours · Sample supervisor profile · Sample project

People make the same decision with and without an AI explanation. The project looks at whether the explanation changes the choice, or only their confidence in it.

A student would run the sessions and analyse the results.

Research area: Human–AI Decision Making

Method

Why this prototype is built this way

Design choiceReason
One joining action, styled as the only solid buttonStudy opportunities are the information a prospective student is usually looking for, so the page keeps a single clear route to it
Requirements shown as a table with unconfirmed values left blankAn unconfirmed number on a university page is worse than an obvious gap
Each person described in their own words, with their pathA short description tells a prospective student more about fit than a job title
Past members kept, with the role they moved intoA student choosing several years of study wants to know what tends to follow
No news feedA page that depends on regular updates becomes misleading when updates stop
One page instead of many sectionsA short page can be kept accurate by one person without specialist tools
Planned website comparison — not yet carried out

The intention is to review a small set of Australian university research-lab websites and record how each one handles the information a prospective student needs. Nothing from this review appears on the page until it is done and checked.

Proposed criteria. Each site would be recorded against the same ten questions:

  1. Is the lab's purpose clear?
  2. Are research areas explained?
  3. Are student projects described?
  4. Are entry requirements available?
  5. Is the application process clear?
  6. Are people and their roles easy to understand?
  7. Are alumni outcomes shown?
  8. Is the information current?
  9. Does the site work on mobile?
  10. Can the navigation be used with a keyboard?

How sites would be selected. Publicly available websites of Australian university research groups in computing or information technology, chosen to cover different universities and group sizes. The selection would be purposive rather than random.

Limitations. A small purposive sample cannot describe university websites generally. Each site would be judged by one reviewer at one point in time, and websites change. The findings would support design decisions for this prototype only.

Recording. Observations would be entered in website-comparison-template.csv in this project, with the review date and a link for each site, so any count on this page can be traced back to a row.
